# 统一发布体验，保留各领域规则

2026-11-09 用户确认统一发布设计访谈第一轮的三个推荐选择：统一用户操作及流程编排，保留各类型的校验、权限和生命周期；根据材料清单识别类型并供用户核对，仅在识别不明确时要求用户判断；将软件纳入统一发现页面及默认搜索，类型作为可选筛选，并取消顶部独立的软件中心入口。

仅聚合旧页面跳转不能解决重复创建项目、版本和上传等操作；将各领域强行合并成一个通用模型则会损失已有规则。因此沿用 [ADR-0001](0001-keep-capability-domains-independent.md) 的领域边界，由统一发布流程编排对应领域的操作，不引入通用 Capability 聚合。识别依据应来自清单，不能仅凭扩展名或是否包含 Skill 判定为独立 Skill 或插件。

第二轮用户确认：新建与更新共用发布流程，识别到已有内容后由用户确认归属和版本，已发布内容不直接覆盖；核对页以“提交发布”为主要操作，串联中间步骤，并保留“保存草稿”；提交后分别呈现待审核、检查中或已发布等真实结果，各类型原有权限和审核要求继续生效。

用户同时确认持久化发布任务：成功步骤保留，失败部分可修复和重试，刷新或重新登录后可以继续。这选择了可恢复的分步完成，而非跨领域整体回滚；实现必须防止重试重复创建内容或重复执行已完成操作，不能仅依赖现有通用请求去重机制。

第三轮用户确认首期仅编排 Skill、插件和软件的已有发布能力，不新增独立 MCP 发布或通用远程导入器；插件内 MCP 配置随插件发布，未识别材料不以“其他”类别放行。依据清单保留组合边界，独立候选项由用户勾选并分别追踪结果；现有 Git、npm 分发配置和证据在统一流程中复用。实施核查确认其为分发渠道而非远程导入器，npm 仓库在核对阶段选择。我的发布统一内容与任务，收起按类型区分的日常管理入口，保留管理员治理配置。

第四轮用户确认自动保存当前发布者的草稿信息、保留显式保存，并明确提示未完成的文件上传；恢复时重新检查权限、替换材料后重新核对、取消任务不撤销已完成内容，并发冲突不静默覆盖。旧链接保留准确上下文或必要的过渡页面，CLI/API 与历史详情保持兼容；详情页使用固定操作位置，按实际能力显示安装、下载、命令或连接配置。

十四项设计选择已逐轮确认，2026-11-09 用户明确调用 implement 后完成整体范围交接并开始实施。完整流程及验收场景见[统一发布设计](../unified-publication-design.md)，实际实现和验证状态以 Wayfinder 实施记录为准。

# Suite 分阶段退出实施说明

日期：2026-10-20。2026-11-06 按用户调用 implement 的授权完成代码实现；Docker 相关验证仍受环境限制。验证结果见 [实施记录](../.scratch/suite-retirement/implementation.md)。

跟踪入口：[Suite 退出与 Plugin 组合交付 Wayfinder](../.scratch/suite-retirement/map.md)。决策票与最终范围核对记录在该图，实施结果另行记录。

## 产品目标

组合技能的发布、安装和更新统一优先使用 Plugin，允许纯 Skill Plugin。Suite 不再作为新的独立产品能力维护。继续支持 Claude Code、Codex、Pi 的原生发行物；每个版本不必同时支持全部宿主。

发布者提供原生插件包，沿用现有校验、审核和分发流程。首期不新增从多个 Skill 自动生成插件包、不自动转换旧 Suite。独立 Skill 与 Plugin 包内组件沿用既有边界，不因 Suite 退出而自动合并或拆分资源。决策依据见 [ADR-0005](adr/0005-consolidate-skill-bundles-under-plugins.md) 和[官方插件规范核查](research/claude-code-skill-only-plugins.md)。

## 第一阶段行为

| 场景 | 预期行为 |
| --- | --- |
| 顶部导航、用户菜单、控制台入口、Skill 详情中的 Suite 推荐入口 | 移除主动推广及新建入口；不将 Suite 新增到能力目录分类中 |
| 旧详情、历史管理与任务链接 | 保留兼容访问，展示停用提示，继续按原有权限限制读取 |
| 创建、编辑、创建新版本、提交新内容 | 服务端拒绝，直接访问旧页面或调用 API 也不能绕过 |
| 新 Bundle 预览与确认 | 停止接收，避免形成新的待处理导入；切换前仅预览但尚未确认的任务不进入执行 |
| 历史发布版本 | 继续详情读取、安装、检查和升级；升级只解析实际已有的合法发布版本 |
| 原有治理操作 | 保留权限检查、成员可用性检查和下架等治理，不因兼容而重新开放不可安装内容 |
| 旧 CLI 本地记录与卸载 | 保留 inventory 和安装来源解析；保留共享成员、本地修改及直接安装的保护行为 |
| 历史数据 | 保留，不物理删除表、成员快照、审核记录、导入记录和安装来源 |

停止新内容是全局产品策略，不由管理员角色自动绕过；既有治理权限仍按原规则判断。停用策略不得只写在控制器或前端里，需要覆盖 app/domain 工作流入口，包含统一审核入口和后台任务调用。

## 已开始流程的收尾

以明确、可持久识别的切换边界区分存量资格，不能仅因为 Suite 已经存在就开放写入。

- 切换前已提交审核的版本，允许对原有提交完成审核和最后一次发布。
- 切换前已确认执行的 Bundle，允许继续成员发布、等待成员审核、创建对应 Suite 草稿并完成该次 Suite 发布。
- 收尾资格绑定具体版本或导入操作及其确认内容，不能用于创建其他版本、修改成员组合或扩大导入计划。
- 普通未提交草稿保留供查看，不允许借重新提交或重开流程恢复新内容发布。
- 审核拒绝或操作取消仍按原流程处理，不自动重开新的发布机会。重试仅服务于同一已确认操作的恢复，不绕过原有重校验。
- 各流程继续检查当前权限、成员状态及原有安全约束；退出 Suite 不自动撤回、删除或改变独立成员 Skill。

## 主要修改位置

1. Web：共享导航、用户菜单、控制台、Skill 关联区域，以及 Suite 创建、编辑、详情、管理和任务页面。保留旧路由的兼容展示，区分停止新内容与允许收尾的操作。
2. 后端：`SkillSuiteAppService`、Suite 草稿/生命周期规则、统一审核入口与 Bundle 预览、确认、重试及执行流程。控制器保持传输职责，停写错误沿用本地化异常与 API 响应约定。
3. CLI 与元数据：保留 `suite install/check/upgrade/remove` 的兼容和 inventory 解析。既然历史安装仍受支持，不能简单移除 `skill-suite-v1` 使旧 CLI 在访问历史内容前失败；展示停用提示不能破坏机器可读输出。
4. 文档：更新 Suite 和 Bundle 使用说明及 Plugin 定位文案，明确新内容通过原生插件包发布，区分停用安排与实际已上线状态。

如需数据库变更，只允许为边界和收尾资格增加必要信息，不删除或重写历史迁移。若 API 合同变化，通过 `make generate-api` 同步生成类型，不手工编辑生成文件。

## 验收条件

- 桌面与移动导航、控制台、用户菜单和 Skill 页面不再引导创建 Suite；旧链接仍可访问相应历史内容。
- 切换后的普通用户及管理员均不能新建、编辑或导入 Suite；覆盖 `/api/v1`、`/api/web` 及统一审核入口，不能通过另一调用路径绕过。
- 历史已发布 Suite 的详情、安装、检查和升级继续工作；成员被隐藏、下架或权限收窄后，仍按原规则拒绝不可用安装。
- 普通未提交草稿不能提交；切换前已提交版本可以收尾，不能借其创建新版本。
- 切换前已确认 Bundle 可在重启和重试后继续同一次操作；只能完成其绑定的成员和 Suite 发布，不能接收新内容或绕过成员审核。
- CLI 卸载不误删共享、直接安装或本地修改的成员；旧 inventory 兼容保持。
- 单独 Skill 的发布与安装，以及三宿主现有 Plugin 导入、审核和分发保持可用。纯 Skill 插件得到明确的正向验证。

实现后运行适当的后端、前端、CLI 与端到端检查；按照仓库要求，在提交 PR 前完成 `make test-backend-app`、`make typecheck-web`、`make lint-web`、`make staging`。检查有阻塞时记录实际结果，不将未执行的验证标记为通过。

## 后续范围

彻底删除旧 API、Suite 模型和数据，自动或按需转换历史 Suite，以及平台自动构包，均不属于第一阶段。不设置未经确认的自动清理日期，后续退出由独立决策明确范围。

## 部署切换

V85 是持久化切换边界。先停止全部旧版本服务实例，备份数据库，再通过正常 Flyway 升级执行 `V85__retire_suite_creation.sql`，随后启动新版本；此次变更不支持新旧写入实例混跑。迁移只新增资格列并标记当时已有的待审核版本及已确认操作，不删除历史记录。多实例必须连接同一已完成迁移的数据库。

`SKILLHUB_SUITE_RETIREMENT_ENABLED` 默认 `true`，对全部用户及管理员停止新的创作。旧 Suite 协议标记继续保留。新记录的收尾资格默认 false，普通未提交草稿不能继承旧任务资格。取消、拒绝和撤回不能重新开放创作；重试仍受原有权限和内容重校验约束。

`false` 仅用于受控回滚或隔离测试中的旧协议验证，不是管理员日常开关：迁移执行后重新开启写入会产生没有存量收尾资格的新内容。回到退出模式时，这些内容不会自动获得继续发布资格。首期不提供修改收尾资格的用户接口。

前端保留旧路由的历史页面和停用提示，创建、编辑与新版本路由展示停用入口；后端独立执行门禁，不依赖浏览器是否更新。历史读取和安装继续按当前权限及成员状态判断。

# 统一发布设计

日期：2026-11-09。状态：十四项选择已确认；用户明确调用 implement，已完成整体范围交接，实施中。实际交付与验证以 Wayfinder 实施记录为准。

决策推进入口：[统一发现与发布 Wayfinder](../.scratch/unified-publication/map.md)。2026-11-09 用户要求先建图；范围最终核对与实施状态在对应子票分别记录。

## 已确认

- Q1：统一入口、操作流程和流程编排，保留各领域实体、权限、校验和生命周期。不能仅聚合旧页面链接。
- Q2：先提供材料，依据清单识别内容类型并供用户核对；识别不明确时再询问，不单凭扩展名判定。插件可以仅包含 Skill。
- Q3：软件纳入统一发现页面及默认搜索，类型作为可选筛选；顶部取消独立软件中心入口。
- Q4：新建与更新共用发布流程；识别已有内容后确认归属、版本。我的发布中的更新操作预填目标；已发布内容不直接覆盖。
- Q5：核对后一次提交，由系统串联中间步骤；保留保存草稿。展示真实的待审核、检查中、已发布等结果，维持各类型既有权限和审核要求。
- Q6：发布任务持久化，保留成功步骤，修复并重试失败部分；刷新或重新登录后可以继续，防止重复执行。
- Q7：首期接入 Skill、插件、软件的已有发布能力；MCP 保留统一发现，插件内 MCP 配置随插件发布，独立 MCP 发布另行建设。无法识别的材料说明原因，不通过“其他”类型绕过校验。
- Q8：多内容材料先核对候选清单，用户勾选后一次提交并分别呈现结果；依据材料清单保留组合边界，不自动将插件拆为独立 Skill。
- Q9：默认本地上传；复用已有 Git、npm 分发能力，在同页按需配置和展示凭证引用及分发证据，不新增通用远程导入器。现有 Git、npm 能力是发布后的分发渠道，并不提供远程来源导入；npm 仓库在核对阶段选择。
- Q10：我的发布统一内容与任务，默认展示内容及版本，可切换查看草稿、检查中、待审核、失败任务；类型作为筛选，具体内容承接复杂管理。收起按类型区分的日常管理入口，保留管理员治理配置。
- Q11：自动保存当前发布者填写的信息，保留显式保存草稿操作；文件尚未上传完成时如实提示。沿用既有内容权限，不新增协作编辑权限。
- Q12：恢复任务重新检查当前权限，权限撤销后停止执行；替换材料重新核对受影响内容；取消仅停止后续操作，不删除或撤回已完成内容，并展示其查看入口；并发修改冲突明确提示，不静默覆盖。
- Q13：旧发布与管理链接能准确映射时跳转新页面并保留上下文，否则保留必要的过渡页面；CLI、API、历史详情链接继续兼容。
- Q14：详情页在固定位置呈现当前内容实际支持的安装、下载、复制命令或查看连接配置等动作，准确表达宿主兼容性和使用方式。

## 用户流程

### 发现与使用

统一发现页默认检索所有支持的内容，包含软件和 MCP 目录；类型只作为可选筛选。用户从结果进入对应详情，在固定操作区域找到适用的实际动作。统一发现不意味着同一个包可以跨宿主安装，也不意味着发布 MCP 配置会创建或修改运行中的连接。

### 新建与更新

1. 从统一发布入口提供本地材料；已有 Git/npm 分发配置及证据在同页按需呈现。
2. 依据清单识别并展示内容；只有识别不明确时才询问类型。独立候选项可勾选，插件组合不自动拆分。
3. 核对归属、名称、版本和必要的类型字段。更新入口预填目标，自动识别出的已有内容也必须由用户确认；已发布内容不直接覆盖。
4. 选择提交发布或保存草稿。系统串联所属领域的创建、上传和提交步骤，用户无需跳转不同管理页。
5. 在同一任务中查看每项进度和真实结果；需要审核、检查或分发的内容继续遵守原有规则。

### 继续与管理

“我的发布”默认展示内容及版本，并可切换查看任务及草稿。从具体内容进入复杂管理。任务在刷新或重新登录后可以继续；每次继续执行检查当前权限，重试不重复已完成操作。

任务进度与内容状态分别表达。例如，插件已完成提交但正在审核时，应显示“待审核”，不能因提交步骤完成而显示“已发布”；批量任务部分失败时仍能查看成功内容，并只修复失败部分。

取消任务不会隐含删除、下架或撤回内容。已经发生的操作仍保留真实结果和查看入口；涉及外部分发的结果应核对后呈现，不能宣称已回滚。

## 实现事实与约束

以下为现状核查，不能代替产品决定。

- 软件发布由 SOFTWARE_ADMIN 或 SUPER_ADMIN 执行；安装包发布仍需元数据确认及满足检查要求。
- 插件离线导入仅产生草稿，后续仍有提交、审核和分发渠道任务，统一流程需要串联这些操作。
- 软件版本标识与插件版本规则不同，不能强行共用 SemVer 校验。
- 插件批量导入已有逐候选项完成及失败结果；统一任务需要准确关联成功内容，避免重复导入。
- 通用请求去重机制不能完整保证任务重放和并发防重复，需要独立处理发布任务的恢复语义。
- 当前 MCP 有目录读取、实体和版本存储，但未发现独立创建、提交和发布 API；独立 MCP 发布需新增后端能力。
- 既有 Suite 退出决定继续有效，见 ADR-0005，不因统一入口恢复新的 Suite 发布。

## 验收场景

以下场景由已确认选择推导，用于验证实现，未完成实现前不得标记通过。

- 同一次发现搜索可检索支持的各类型内容；筛选类型后结果正确，软件详情仍支持适用的下载操作。
- 发布者从一个入口完成 Skill、插件、软件各自的既有发布路径，过程中无需进入类型专用管理页完成中间操作。
- 为已有内容更新版本时能预填目标并确认归属；不会覆盖已发布内容或套用错误的版本规则。
- 识别不明确或不支持的材料得到明确反馈；含多个 Skill 的插件保持其组合边界。
- 多候选项任务仅处理用户选择的内容；成功项和失败项分别显示，重试不重复成功项。
- 填写后离开并返回能继续草稿；文件未上传完成时不误报材料已经保存。
- 创建版本后上传失败，刷新或重新登录可继续；重复提交及并发继续不会重复创建或静默覆盖。
- 恢复前权限被撤销时阻止后续执行；替换材料后重新核对受影响部分。
- 取消任务后已完成内容保留且可查看；待审核、检查中和已发布状态不混淆。
- 旧发布和管理链接保留正确上下文或进入过渡页面；原有 CLI/API 及历史详情访问继续有效。
- 统一界面在桌面与移动端均可完成主要任务，键盘可操作，上传、保存、错误和恢复提示清晰可见。

## 实施边界

首期交付包含统一发现、统一发布、我的发布和支撑它们的后端任务编排及恢复能力；仅修改导航或复用旧页面跳转不足以验收。保留所属领域的权限与生命周期、管理员治理配置和既有客户端协议；不新增独立 MCP 发布、通用远程导入器、协作编辑或通用 Capability 聚合，也不恢复 Suite 新发布。
